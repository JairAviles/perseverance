Open MCT, mapped for Percy

Open MCT is a dashboard that knows nothing about any spacecraft: plugins tell it what things exist and hand it numbers with timestamps, and it draws them.

The map

The core is small. It creates one object called openmct, hangs a set of service desks on it (the APIs), and waits. A plugin is a function that walks up to a desk and registers something: a kind of object, a data source, a clock, a view.

How We Connect Percy

Our simulation already knows Percy's speed, heading and position on every frame (src/rover.js in our project). Open MCT needs two things from us: a list of what Percy can measure, and the readings themselves. That is one plugin. Nothing below is built yet.

What the Percy plugin registers

  1. A type. "Percy measurement", so Open MCT knows what kind of thing speed is. Desk: src/api/types/TypeRegistry.js:59. Example: example/generator/plugin.js:64. Docs: API.md:278.
  2. A root folder. "Perseverance" appears in the tree. Desk: src/api/objects/ObjectAPI.js:498. Example: src/plugins/staticRootPlugin/plugin.js:54.
  3. An object provider. Answers "what is inside Perseverance?" with one object per measurement. Each one carries labels: a utc field marked as time and a value field marked as the number to plot. Desk: src/api/objects/ObjectAPI.js:168.
  4. A telemetry provider. subscribe for live readings, request for past ones. Desk: src/api/telemetry/TelemetryAPI.js:167. Example: example/generator/GeneratorProvider.js:91 and :101. Docs: API.md:532.
  5. Install it on the page, the same way the generator is installed at index.html:104.
// Sketch only, not tested. "feed" is the relay connection, "lookup" returns the objects.
function PercyPlugin() {
  return function install(openmct) {
    openmct.types.addType('percy.telemetry', { name: 'Percy Measurement' });
    openmct.objects.addRoot({ namespace: 'percy', key: 'rover' });
    openmct.objects.addProvider('percy', {
      get: (identifier) => Promise.resolve(lookup(identifier))
    });
    openmct.telemetry.addProvider({
      supportsSubscribe: (object) => object.type === 'percy.telemetry',
      subscribe(object, callback) {
        const listener = (reading) => callback(reading); // { utc, value }
        feed.on(object.identifier.key, listener);
        return () => feed.off(object.identifier.key, listener);
      }
    });
  };
}

Three rules that are easy to miss

  1. The time field must be named after the active time system. With the UTC plugin that name is utc, which is why the plot picks it as x (src/plugins/plot/configuration/PlotSeries.js:124).
  2. subscribe must return a function that stops the feed. Open MCT calls it when the last view closes.
  3. Past readings come back oldest first, and only inside the requested start and end.
Limits of this map: live readings alone are enough to see a moving chart, but scrolling back in time needs request, which means something has to keep Percy's past readings. Our simulation does not model a battery, so that measurement would have to be invented.
